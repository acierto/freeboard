Documentation

Freeboard watches the free space on your disk and helps you get it back without breaking anything. Here is how to install it, what each part does, and why cleanup stays safe.

Get started

Download the installer for your system from the download page or the latest release, and compare its SHA-256 with SHA256SUMS.txt. Preview builds are not yet signed or notarized, so the first launch needs one confirmation.

On first run Freeboard explains what it reads and asks which folders to scan for projects and worktrees. It asks the operating system for a permission only when a feature needs it.

How it watches your disk

Freeboard monitors your home volume, plus any other fixed volume you add. It samples free space every 5 minutes and keeps one sample per hour.

StatusDefault ruleTray iconNotification
● Healthy20 GB free or moreNeutral ringNone
◆ LowBelow 20 GBAmber ringOnce, on entering Low
▲ CriticalBelow 8 GBRed ringOn entering Critical, then every 6 hours while unchanged

A status improves only after free space rises 2 GB above its threshold, so you aren't alerted again and again around the limit. The forecast ("About N days left") appears only with at least 3 days of samples and falling free space; earlier cleanups are excluded from the estimate.

Closing the window hides Freeboard in the tray. Monitoring and scheduled scans keep running, and the interface is released after 60 seconds hidden. The tray menu offers Open Freeboard, Scan Now, Pause Notifications and Quit.

Making room

Pick a goal (20 GB, 50 GB, 100 GB or All I can) and optionally Where from. Freeboard fills the pile with Safe items, largest first, until the goal is met. Items you added by hand come first.

  • Review and Risky items are never added automatically.
  • Take a crate out and the pile switches to manual mode and won't refill it. Pick a size again to refill.
  • Keep marks an item you never want suggested. Stop keeping brings it back.
  • Choose which picks individual projects, models, emulators, apps, backups or versions inside an item.
  • If Safe items fall short of the goal, Freeboard says by how much and points to the items below.

Risk levels

● Safe

Regenerable data: caches and build output that tools recreate. Preselected. Recover by rebuilding with the tool that owns it.

◆ Review

Usually fine, worth a look: unused images, idle projects' dependencies, merged worktrees. Moved to the Trash where possible.

▲ Risky

Cannot be recovered, such as Docker volumes. Never preselected; you confirm each one by name.

Moving something to the Trash doesn't free space until you empty the Trash. The plan shows this up front.

Confirming a cleanup

Before anything runs you see a plan with three totals: freed right away, held in the Trash, and cannot be recovered. Each unrecoverable item needs its own confirmation.

Then, one item at a time:

  1. Freeboard checks it again. If it changed since the scan (a worktree got a commit, a container started, a folder was modified), it is skipped and the reason is shown.
  2. It runs the action.
  3. The result is recorded in the Logbook.

You can cancel between items; an item already running is never interrupted. If one fails, the rest continue. Afterwards Freeboard measures free space again and reports the measured change next to the expected one. A plan expires after 30 minutes, or sooner if a new scan runs.

Keep me tidy

Optional rules, off by default: clear package caches over 30 days old when space is Low, and clear unused Docker build cache weekly. They can only touch named Safe detectors.

What Freeboard never does

  • Removes anything without a plan you confirmed.
  • Touches system or application folders, your home folder's main folders, or .ssh.
  • Deletes a repository root or anything inside .git.
  • Follows symbolic links out of the folder being cleaned.
  • Uses force flags, except Docker's own prune commands after you confirm.
  • Runs commands through a shell.
  • Sends data anywhere. No account, no telemetry, no network access.

FAQ

Why does a size say "about"?

Some data is shared (hard links, as with pnpm) or unreadable. Freeboard reports only the space removal would actually free, and marks the number as an estimate when it can't be exact.

Why was an item skipped?

It changed after the scan, or Freeboard couldn't confirm its state because a tool was missing or timed out. Skipped items stay in Suggestions with the reason.

Why didn't free space grow after a cleanup?

Items moved to the Trash free space only when the Trash is emptied.

Something looks wrong.

Please open an issue on GitHub.

Build from source

Freeboard is a Tauri 2 app. A Rust core does all monitoring, scanning and cleanup; a React interface displays results and sends IDs back. You need Rust stable, Node 24 and, on Linux, libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev patchelf.

npm ci
npx tauri dev                                      # run with hot reload
npx tauri build                                    # unsigned installers
cd src-tauri && cargo test --no-default-features   # core tests

Tests use temporary directories, temporary Git repositories and fake tools, and never run cleanup on your machine.
